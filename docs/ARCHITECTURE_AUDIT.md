# JaguarBase: Technical Architecture & Security Audit Report

**Release Status:** Beta (v1.0.0)  
**Scope:** Static Code Analysis, Data Flow Verification, Protocol Conformance & Governance Lifecycle  
**Objective:** Technical Debt Mapping, Logical Vulnerability Remediation & v1.1.0 Roadmap  

---

## 📌 Executive Summary

JaguarBase exhibits solid systems engineering foundations in Go: clean layered architecture, minimal attack surface via distroless non-root containers, a zero-warning GoSec clean build, native CGO DuckDB integration, and edge-resilience mechanisms including O(1) Load Shedding and strict HTTP timeouts.

However, an in-depth semantic audit identified **critical architectural misalignments between subsystems**, specifically in how schemas are dynamically mapped across the ingestion pipeline, cache lifecycle handling, and protocol compliance. This document consolidates all prioritized findings to serve as the definitive specification for the platform's v1.1.0 hardening.

## 🔴 Priority 1 Findings (Critical Correctness, Data Loss & Security)

### 1. Ingestion Payload Mapping Bypass (`content_column`)
* **Target Components:** `internal/ingestion/postgres_adapter.go`, `internal/ingestion/pipeline.go`, `internal/dynamic/processor.go`
* **Root Cause:** In the real-time PostgreSQL adapter, columns named `message` or `content` were extracted into `RawRecord.Content` and omitted from the generic metadata map. During pipeline ingestion (`pipeline.go`), `rawMap` was populated with `content`, but the column name configured in `jaguardb.yaml` (e.g., `message`) was not restored. When `ProcessRow` executed, it evaluated the declared `message` column as `nil`.
* **Impact:** The `untrusted_input` scanner was bypassed for real-time events on custom column names, allowing tainted payloads to be persisted with `_is_tainted = false`. Furthermore, PII vault tokens were stored under the custom column in metadata while unmasked `Content` leaked to the embedder.
* **Remediation Implemented (`fix/gringo-audit-remediation`):**
  - Canonical schema mapping implemented in `postgres_adapter.go` and `pipeline.go`.
  - `record.Content` is mapped under both the canonical `content_column` and fallback `content`.
  - The exact sanitized string generated by the governance processor is synchronized to `contentToVectorize`, the embedder, and DuckDB storage.
  - Regression tests added in `internal/ingestion/pipeline_test.go`.

---

### 2. Event Loss Race Window Between Historical Backfill and Real-Time Stream
* **Target Components:** `internal/ingestion/pipeline.go` (`Start` and `performBackfill`)
* **Root Cause:** `Start` previously executed `performBackfill` synchronously before spawning the real-time `source.Watch` listener (which executes the PostgreSQL `LISTEN` command).
* **Impact:** Any `INSERT` or `UPDATE` occurring on PostgreSQL during snapshot backfill emitted a `NOTIFY` that was permanently dropped, as no listener had subscribed yet. Standard `LISTEN/NOTIFY` provides no durable replay for offline clients.
* **Remediation Implemented (`fix/gringo-audit-remediation`):**
  - Real-time watcher `source.Watch` starts immediately in `Start` with an asynchronous 2048-capacity buffer channel before backfill begins.
  - Historical backfill runs concurrently/subsequently.
  - The DuckDB idempotent upsert layer reconciles any overlapping records without duplicate keys or inconsistent vector cache state.

---

### 3. Partial Batch Ingestion Failures Advancing Checkpoint Pointers
* **Target Components:** `internal/ingestion/pipeline.go` (`performBackfill`, `processRecord`)
* **Root Cause:** `processRecord` returned `void` without propagating errors back to the backfill loop. If an intermediate step failed (e.g., Ollama embedding timeout or database write error), the failure was merely logged while `totalSynced` incremented and `lastID` advanced.
* **Impact:** Records that failed to ingest were skipped permanently. On restart, DuckDB's `GetMaxID` queried the highest recorded ID, leaving permanent silent data gaps in the local cache.
* **Remediation Implemented (`fix/gringo-audit-remediation`):**
  - Refactored `processRecord` signature to return explicit `error`.
  - Added bounded retry mechanism (3 attempts with exponential backoff) for transient errors in backfill.
  - If retries are exhausted, `performBackfill` returns an error and halts without advancing `lastID` past the failing record, preventing silent gaps and allowing clean resumption.
  - Unit tests added in `internal/ingestion/pipeline_test.go`.

---

### 4. Cache Desynchronization: Lack of Primary Key Constraints, Upserts, and Deletions
* **Target Components:** `internal/engine/duckdb.go` (`AutoMigrate`, `InsertBatch`), `internal/ingestion/pipeline.go`
* **Root Cause:** DuckDB table schemas created by `AutoMigrate` and `InitSchema` lacked an explicit `PRIMARY KEY (id)` constraint. `InsertBatch` executed blind `INSERT INTO` statements without upsert logic.
* **Impact:** Updates on the primary PostgreSQL database created duplicate rows with the same ID in DuckDB, retaining outdated vector embeddings.
* **Remediation Implemented (`fix/gringo-audit-remediation`):**
  - Enforced `id VARCHAR PRIMARY KEY` in `AutoMigrate` and `PRIMARY KEY` in `InitSchema`.
  - Implemented dynamic idempotent upsert (`INSERT OR REPLACE INTO`) in `InsertBatch` whenever a primary key is defined.
  - Regression tests added in `internal/engine/duckdb_test.go`.

---

### 5. Model Context Protocol (MCP) Lifecycle Non-Conformance
* **Target Components:** `internal/server/mcp.go`
* **Root Cause:** The HTTP JSON-RPC router only accepted `tools/list` and `tools/call`. Official MCP client specifications (Anthropic Model Context Protocol) mandate an initial handshake: `initialize` followed by `notifications/initialized`.
* **Impact:** Standard MCP clients (Claude Desktop, Cursor MCP connector) failed during handshake with `-32601 Method not found`.
* **Remediation Implemented (`fix/gringo-audit-remediation`):**
  - Implemented `initialize` returning server capabilities, protocol version (`2024-11-05`), and server metadata (`jaguarbase v1.0.0`).
  - Implemented `notifications/initialized` returning 204 No Content for notification semantics.
  - Implemented `ping` keepalive handler.
  - Unit tests added in `internal/server/mcp_test.go`.

## 🟡 Priority 2 Findings (Hardening, Governance & Technical Realism)

### 6. Heuristic Anti-Injection Scanner Boundaries
* **Target Components:** `internal/governance/scanner.go`
* **Analysis:** The detector relies on an RE2 regex matching 3 static evasion patterns (`ignore...instructions`, `acesso...root`).
* **Engineering Directive:** Formally documented in `README.md` and `README.pt-BR.md` as a **first-line heuristic filter**, not a cryptographic or mathematical injection firewall. Downstream consumers are instructed to treat retrieved context as untrusted input.

---

### 7. PII Vault Lifecycle, Entropy, and Scope
* **Target Components:** `internal/governance/vault.go`
* **Analysis:**
  - Sensitive plaintext is stored reversibly in Redis under a 24-hour TTL (`vault_{token}`). This is **stateful session pseudonymization**, not irreversible anonymization.
  - Truncating HMAC-SHA256 to 16 hex characters yields 64 bits of entropy. While safe against precomputation, 64-bit truncated hashes are not collision-immune at high scale.
* **Engineering Directive:** Documented the vault as a reversible session tokenization cache. v1.1.0 roadmap schedules expanding hash length to 128 bits (32 hex characters) with collision mitigation.

---

### 8. Exact Cosine Distance (SIMD) vs. Approximate Vector Indexing (ANN/HNSW)
* **Target Components:** `internal/engine/duckdb.go`
* **Analysis:** The engine computes exact brute-force cosine distance (`array_cosine_distance`) accelerated by DuckDB's C++ SIMD instructions. Although the VSS extension is loaded (`INSTALL vss; LOAD vss;`), no `CREATE INDEX ... USING HNSW` is created on the vector column.
* **Engineering Directive:** Clarified in documentation that the engine currently provides **Exact k-NN via SIMD**, guaranteeing 100% recall for tens/hundreds of thousands of vectors. True HNSW index creation is scheduled for larger-scale workloads.

---

### 9. gRPC Transport Security Boundaries
* **Target Components:** `cmd/jaguarbase/main.go`, `internal/server/grpc.go`
* **Analysis:** The gRPC server listens on `:50051` without transport credentials or metadata authentication interceptors (`JAGUARBASE_API_KEY` only shields HTTP/MCP).
* **Engineering Directive:** Provide an optional metadata interceptor (`Authorization: Bearer <token>`) for deployments where the gRPC port is exposed beyond trusted localhost/service mesh perimeters.

---

### 10. Memory Accounting Methodology in Benchmarks
* **Target Components:** `cmd/chaos/breaking_point/main.go`, `docs/BENCHMARKS.md`
* **Analysis:** `getProcessMemoryMB` relies on `runtime.MemStats.Alloc`, which only tracks the Go runtime managed heap (<10MB). Because DuckDB allocates native C++ memory outside the Go runtime via CGO, this does not represent the process's true Resident Set Size (RSS).
* **Engineering Directive:** Collect metrics from `/proc/self/statm` or OS cgroups to report accurate total physical memory consumption in future benchmark publications.
